# 예울마루 STAY 패키지 — 객실 선택

문자로 링크를 보내면 예매자가 폰에서 **휴대폰 뒷 4자리로 본인 확인 → 객실 형태 선택**까지 하는 프로그램.
외부 라이브러리 0 · 빌드 0 · `node_modules` 0.

```
public/index.html        고객 화면 (본인 확인 → 객실 선택 → 완료)
public/admin.html        관리자 화면 (명단·공연/날짜·수량·현황·취소)
functions/api/book.js    서버 전부
tools/rooms.mjs          관리자 CLI — 터미널에서 현황 확인
tools/dev.mjs            로컬 미리보기 서버
test.mjs                 검증 58축 (node test.mjs)
CLAUDE.md                클로드코드용 안내
docs/인수인계.md          계약·실측·다음 후보
```

## 1. 어떻게 도는가

1. 담당자가 예매자에게 **링크를 문자로 보낸다**
2. 예매자가 링크를 열고 **휴대폰 번호 뒷 4자리**를 입력한다
3. 명단에 있으면 통과, 없으면 막힌다 — **명단에 없는 번호는 아예 못 들어온다**
4. **숙박일은 고객이 고르지 않는다.** 예매한 공연 날짜가 곧 숙박일이고, 명단에 미리 박혀 있다.
   화면에는 「예매 확정 내역 · 변경 불가」로 공연명과 체크인/체크아웃이 그대로 뜬다.
5. **스탠다드 더블 / 스탠다드 트윈** 중 남은 것만 고를 수 있다. 마감된 종류는 눌리지 않는다.
6. **저장하기 → 확인** 두 단계를 거치면 접수되고, 그 순간 잔여 수량이 하나 줄어든다
7. 완료 화면에 「감사합니다 · 추후 문자로 안내드리겠습니다」와 접수 내역·숙소 안내·문의처가 뜬다
8. 같은 번호로 다시 들어오면 **자기가 고른 내역만** 뜬다(다시 못 고른다)

공연명·날짜·수량은 관리자 화면이나 CLI에서 바꿀 수 있다.

## 2. 현황은 터미널에서 본다 (관리자 GUI 없이)

```bash
node tools/rooms.mjs              # 남은 객실
node tools/rooms.mjs list         # 선택 완료 목록
node tools/rooms.mjs pending      # 아직 안 고른 사람 (재안내 대상)
node tools/rooms.mjs all          # 셋 한 번에
node tools/rooms.mjs who 1234     # 한 사람 조회
node tools/rooms.mjs cancel 1234  # 선택 취소 (자리 즉시 재개방)
node tools/rooms.mjs roster 명단.txt   # 명단 통째 교체
node tools/rooms.mjs csv          # 탭 구분(엑셀 붙여넣기)
```

접속 정보는 저장소 루트의 `.booking.json` 에 넣는다(`.gitignore` 에 들어 있어 커밋되지 않는다):

```json
{ "url": "https://<배포주소>", "pin": "<BOOK_PIN 값>" }
```

환경 변수 `BOOK_URL` · `BOOK_PIN` 으로 줘도 된다.

## 3. 배포 전에 화면 먼저 보기

```bash
node tools/dev.mjs          # http://localhost:8788
```

R2를 메모리로 흉내 내고 명단·공연·수량을 미리 채워 둔다. 서버를 끄면 데이터도 사라진다.
시드 번호 — `1234`(9/12 김예울) · `5678`(10/14 이마루) · `9012`(10/27 박여수) · `3456`(이름 없음) · `7777`
관리자 비번 `dev1234` · 현황은 다른 창에서 `node tools/rooms.mjs --local`

## 4. 설치 (한 번만)

Cloudflare Pages에 붙인다. 고객이 문자 링크로 바로 들어와야 하므로 **로그인 벽(Access) 없는 프로젝트**여야 한다.

1. Cloudflare → Workers & Pages → **Create → Pages → Connect to Git** → 이 저장소
2. 빌드 설정
   - **Root directory** : 비움(저장소 루트)
   - **Build command** : 비움
   - **Build output directory** : `public`
   - Framework preset : None
   - ⚠ `Build output directory` 칸이 안 보이면 Pages가 아니라 Workers다 — 뒤로 가서 Pages로 다시
3. 생성 후 **Settings → Bindings → R2 bucket**
   - Variable name : **`R2`** (정확히 이 이름)
   - Bucket : 아무 버킷 (키는 전부 `booking/` 밑에만 쓴다)
4. **Settings → Variables and Secrets** → `BOOK_PIN` = 관리자 비번(아무 문자열)
   - 이 값이 없으면 관리자 기능은 통째로 잠긴다(빈 비번으로 열리는 일 없음)
5. 배포 후 나오는 주소가 곧 **고객 링크**. 관리자 화면은 그 주소 + `/admin.html`

### 배선 확인 3줄
1. `/admin.html` 접속 → 비번 입력 → **"저장소(R2)가 연결되지 않았어"** 면 3번을 다시(바인딩 이름 확인)
2. **"관리자 비번(BOOK_PIN)이 아직 설정되지 않았어"** 면 4번을 다시
3. 명단 한 줄(`1234, a, 테스트`) 저장 → 고객 주소에서 `1234` 입력 → 공연 날짜와 객실 2종이 보이면 끝

## 5. 쓰는 순서

1. 관리자 화면(`/admin.html`) 또는 CLI로 **공연명·날짜·수량**을 확인한다
2. **명단 등록** — 한 줄에 한 명씩. 엑셀 세 칸을 그대로 복사해 붙여넣어도 된다.
   ```
   1234, a, 홍길동
   5678, b, 김철수
   9012, c
   ```
   - 첫 칸 = 휴대폰 뒷 4자리 (숫자 4자리)
   - 둘째 칸 = **어느 공연을 예매했는가** (a / b / c) → 이게 그 사람의 숙박일이 된다
   - 셋째 칸 = 이름 (없어도 된다)
   - **저장하면 기존 명단은 통째로 교체된다**
   - 뒷 4자리가 겹치면 뒤엣것을 버리고 어떤 번호가 겹쳤는지 알려준다
3. 고객에게 링크 문자 발송
4. 현황은 `node tools/rooms.mjs` 로 확인. 안 고른 사람은 `pending` 으로 추려 다시 문자한다

## 6. 두 사람이 동시에 마지막 한 자리를 눌러도 안 겹친다

수량을 한 파일에 적어두고 빼는 방식이 아니다. **선택 1건 = 파일 1개**를 각자 자기 번호로 만들고,
만든 뒤 전체를 다시 세어 정원 안에 드는지 확인한다. 밀렸으면 자기 파일을 지우고 "방금 마감됐어요"로 답한다.
순서 기준이 (시각, 뒷4자리)라 두 요청이 같은 판정을 내리므로 **한 명만 살아남는다.**
검증 = `node test.mjs` [5]번 (6명 동시 클릭 · 남은 4자리 → 성공 정확히 4명).

## 7. 알아둘 것

- 선택을 되돌리려면 `node tools/rooms.mjs cancel 1234` 또는 관리자 화면의 `취소`. 그 자리는 즉시 다시 열린다.
- 명단에 없는 번호는 못 들어온다. 현장에서 추가하려면 명단에 그 줄을 넣고 다시 저장한다.
- **뒷 4자리가 겹치는 예매자**는 지금 뒤엣사람이 버려진다(겹친 번호를 화면에 알려준다). 실제로 생기면 이름까지 같이 묻는 방식으로 넓혀야 한다 — `docs/인수인계.md` §6-a.
- 데이터는 R2의 `booking/` 밑에 있다 (`roster.json` 명단 · `stock.json` 공연/날짜/수량 · `bk/<뒷4자리>.json` 선택 1건).
- 문자 발송은 이 프로그램 밖이다. 링크만 넘긴다.
